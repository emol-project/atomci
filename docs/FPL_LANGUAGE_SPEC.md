# FPL Language — Practical Reference (for maintainers)

> **Note**: source-tree paths in this doc (`include/`, `fplincl/`, `.f`, `.fpl`, …) are relative to `src/` unless noted.

A practical, quick-reference note to skim before reading or editing the `*.fpl` files in this
codebase. This is **not** an exhaustive formal grammar. The authoritative language reference is
`docs/fpl90.doc` (FPL90 MANUAL, JAN 1993); this document supplements it with how FPL is actually
used in this codebase (the Unix build) — see Section 5.

The statements here are grounded in these primary sources (not guesses): `docs/fpl90.doc`; the
preprocessor itself, `fpl90.f` / `fpl90.fpl`; and the real `*.fpl` files (`setcfp.fpl`,
`cfpset.fpl`, `wt9x.fpl`, `cici.fpl`, etc.) together with the macro definitions under `include/`.

---

## 1. Overview

**What FPL (FPL90) is**: a home-grown macro / structured-programming preprocessor language built
on top of FORTRAN. It lets you write algorithms in block structure without goto/statement numbers,
and generate code via macros. The preprocessor itself is written in FPL (self-hosting:
`fpl90.fpl` → `fpl90.f`).

**Why it's used**: back in the 1980s–90s, to get structured control flow (`IF/THEN/ELSE`,
`WHILE`, `DO CASE`, internal procedures) and macros (sharing constants, COMMON blocks, boilerplate,
and code templates) that plain FORTRAN 77 lacked. As a result `*.fpl` is concise, but the generated
`*.f` is full of gotos and statement numbers (e.g. the `IQ....` computed-GOTO dispatch in `wt9x.f`).

**Position in the build pipeline**:

```
   *.fpl  ──[ fpl preprocessor ]──▶  *.f  ──[ gfortran ]──▶  *.o ──▶ atomci
   (the source of record)          (generated / auto-produced)     (executable)
```

- The `fpl` binary is built by `make` from `fpl90.f` (+ `fpl90lib.f`, `iqtime.c`); `fpl90.f`
  itself is generated by `tfpl < fpl90.fpl` (see the Makefile).
- **`*.f` files are generated artifacts**. They may be regenerated from `*.fpl` on every build
  (each `*.f` begins with a `*     GENERATED BY FPL90 ...` header). **Edit the `*.fpl` (the source
  of record)** — editing a `*.f` directly is overwritten on the next build.
- Therefore, fix/change the `*.fpl` and regenerate with `./fpl < X.fpl` to produce `X.f`.

## 2. Basic syntax

### 2.1 Source format, case, indentation
- The heritage is card images (`docs/fpl90.doc §2.1`: write in columns 2–72; columns 73–80 are for
  identification). In practice the `*.fpl` files are written mostly free-form within columns 2–72.
- **Case is not significant**. The emitted FORTRAN is normalized to **all-uppercase, fixed form**,
  and auto-indented by block structure (`setcfp.fpl` is lowercase → `setcfp.f` is uppercase).

### 2.2 Statements are separated by semicolons `;`
- The statement separator is `;`. **If a line does not end with `;`, the preprocessor supplies one**
  (`docs/fpl90.doc §2.1`). So one-statement-per-line lets you omit `;`, but `;` matters when you put
  multiple statements or a `DO ... END` on a line.

### 2.3 Continuation `--` (also serves as an end-of-line inline comment)
- **`--` (two hyphens) is the continuation symbol**. From `--` to end of line is ignored, and the
  next card is logically joined (`docs/fpl90.doc §2.2`). In other words, you can write a comment
  after `--`:
  ```
  subroutine %subname ( nftf ) --   this text is ignored; continues on the next line
  ```

### 2.4 Comments `/` and `/*` ── ★ the most important gotcha (see Section 4)
- A **`/`** at the start of a logical line begins a comment. It is a comment **until a `;` is
  encountered** (`docs/fpl90.doc §2.3`). This `/` comment does **not** appear in the FORTRAN output.
- A comment starting with **`/*`** is **copied** into the FORTRAN output as a `*` comment line
  (this is what `include/CPYRIGHT`'s copyright banner and each file's `/* FUNCTION : ...` notes are).
- **Both are terminated by `;`.** → Writing a `;` inside a comment ends the comment there, and the
  rest of the text leaks out as Fortran (Section 4).

### 2.5 Logical-operator alias notation
You can write FORTRAN `.XX.` operators as symbols (`docs/fpl90.doc §3 <logical expression>`):

| FPL | `=` | `>` | `<` | `^=` | `>=` | `<=` | `^` | `&` | `!` |
|---|---|---|---|---|---|---|---|---|---|
| FORTRAN | `.EQ.` | `.GT.` | `.LT.` | `.NE.` | `.GE.` | `.LE.` | `.NOT.` | `.AND.` | `.OR.` |

Example: `IF NFQ + 1 = NGQ & NFQ > 0` → `IF (NFQ+1.EQ.NGQ .AND. NFQ.GT.0)`

### 2.6 Blocks and structured control (no goto/statement numbers)
- Blocks: `begin ... end` / `do ... end` / **`( ... )`** (a `DO`…`;END` pair may be replaced by
  parentheses).
- Main control constructs (`docs/fpl90.doc §3`):
  `IF <expr> THEN <stmt> ELSE <stmt>` / `FOR i=1,n; <stmt>` (→ DO loop) / `WHILE <expr>;<stmt>` /
  `UNTIL <expr>;<stmt>` / `DO WHILE <expr>` / `DO UNTIL <expr>` /
  `DO CASE OF <var>` (arithmetic), `DO CASE OF <var>;CHARACTER` (character), `DO CASE LOGICAL`
  (logical) / `EXIT` (leave the block; in the outermost block it is effectively `RETURN`).
- Self-update of a variable: `= VAR <rest of expr>` means `VAR = VAR <expr>`. Example `= n + 1`
  → `N = N + 1`.

### 2.7 Internal procedures (parameterless) and `EXEC`
- Definition: `PROCEDURE <name> [; RECURSIVE] ; <block>`. Call: `EXEC <name>`.
- **They take no arguments** (all variables are shared with the enclosing scope). Add `RECURSIVE`
  only for procedures that may recurse; return addresses are pushed on stack `IQ9998` with pointer
  `IQ9999` (`docs/fpl90.doc §3 note`).
- In the generated `*.f`, `EXEC`/`PROCEDURE`/`DO CASE` expand into **statement numbers and computed
  GOTOs** (`GO TO(...),IQnnnn`, or arithmetic IFs). The tangled control flow in `wt9x.f` is exactly
  this.

### 2.8 I/O, formatted output, raw FORTRAN
- `FORMAT|BINARY READ|WRITE ... ; (format)`, `PUT V I5` (integer) / `PUT S C LEN` (character
  string), `LIST`, line-spec `1P` (new page) / `3L` (line feed) / `5X` (skip columns) / `33C`
  (column position) (`doc §3`).
- **`FORTRAN <stmt>`** / **`DO FORTRAN ... END`**: an escape hatch that passes raw FORTRAN straight
  through to the output.

### 2.9 Macros (the workhorse of this codebase)
- **Definition**: `%%<name> <text>%` (closed by a trailing `%`). Examples: `%%SUBNAME WT9X%`,
  `%%WORKCORE 430 000 002%`. The text may contain nested `%othername` references
  (`docs/fpl90.doc §4`).
- **Reference**: `%<name>`. If defined, it is substituted with the text.
- **Blanks in the text are insignificant to FORTRAN**: `%%WORKCORE 430 000 002%` is defined with
  blanks for readability, but expands to the integer `430000002` (confirmed in `ci.f`).
- **Auto-inclusion from `include/`**: referencing an undefined `%NAME` (uppercase) loads the
  corresponding macro library `include/NAME`. Real examples:
  - value macros … `include/PARAM` (`%WORKCORE`, `%BASIS`, `%CLIMIT`, …), `include/FILETBL`
    (file unit numbers such as `%NFWFB0` = 31)
  - COMMON blocks … `%COMCFP` → `include/COMCFP`, `%COMWFA` → `include/COMWFA`
  - boilerplate … `%CPYRIGHT` (copyright), `%UPDATE` (revision-history comment)
  - code templates … `%WKCORE` / `%ALLOC` / `%CHECK` / `%IOCHECK` / `%ACTION` / `%CFPXX`, etc.
    ("pseudo-function macros" that you expand after pre-setting their arguments via other macros
    like `%%VNAME ..%`, `%%TYPE ..%`)

### 2.10 The `PROCESS` directive (output file name, listing control)
Compilation directives placed near the top (`docs/fpl90.doc §3 <process option>`). Real usage:
```
   %%SUBNAME CFPSET%
   PROCESS   NO LIST   MAP   HEADER  %SUBNAME     … suppress listing; procedure map; header
   process   file 'cfpset.f'                       … set the output Fortran file name
```
- `NO LIST` suppress the source listing / `MAP` list internal procedures / `HEADER <name>` header /
  `FILE 'x.f'` output file name / `INCLIB` macro-inclusion source.

## 3. Examples (`*.fpl` → generated `*.f`)

### Example 1: basic macro expansion (`setcfp.fpl` → `setcfp.f`)

FPL source (excerpt):
```
 %%subname setcfp%                         … macro definition
 process  no list file '%subname.f'        … output name setcfp.f
 subroutine %subname ( nftf )              … %subname → SETCFP
    %update                                … expands to the revision-history comment
    implicit real * 8 ( a-h,o-z )
    %COMCFP                                … expands to COMMON /COMCFP/...
    begin
       rewind nftf
       read (nftf) INAME,IBEL,ICNN,...
       ...
       end
```
Generated FORTRAN (excerpt):
```
      SUBROUTINE SETCFP(NFTF)                      ← lowercase→uppercase, fixed form
*     GENERATED BY FPL90 V(AIX OS   Jan10 18) ...  ← header/history from %update
*            Revised  by M. SEKIYA ON Aug. 31 1990 ...
      IMPLICIT REAL*8(A-H,O-Z)
      COMMON /COMCFP/CMTTBL(8000)                  ← expansion of %COMCFP
      COMMON /COMCFP/INAME(18),IBEL,ICNN,ILFN,...
      ...
      REWIND NFTF
      READ (NFTF)INAME,IBEL,ICNN,ILFN,ICMTN,ICDX,IMMINT,ILSTAD
```
Key points: substitution of `%subname`/`%update`/`%COMCFP`; `begin/end` are structural only (the
words don't appear in the output); lowercase→uppercase; `/` comments do not survive into the output.

### Example 2: value macro (`include/PARAM`)
```
  %%WORKCORE 430 000 002%     (definition; blanks are for readability, insignificant)
      ↓  reference %WORKCORE
      COMMON /WORK/VAR(430000002)      ← in the generated ci.f this is 430000002
```

### Example 3: `DO CASE` and `EXEC` → arithmetic IF + computed GOTO (`wt9x.fpl` → `wt9x.f`)

FPL source (excerpt; `%I`, `%CXXX`, … are macros mapping "operator kind → case number"):
```
     DO CASE OF MODEOP ;
       %I : --
           IF WFG = WFF & NFQ = NGQ
           THEN ET = DSQRT( DFLOAT( FSX * FRX ) ) ;
           ELSE   ET = 0.0D0
       %CXXX :
       %XXCX : --
           IF NFQ + 1 = NGQ
           THEN ET = CFP(WFG,WFF,NREL, 1)
           ELSE ET = 0.0D0
       ...
```
Generated FORTRAN (excerpt):
```
      IF (0-MODEOP)1036,1035,1033      ← DO CASE expands into a chain of arithmetic IFs
 1036 IF (1-MODEOP)1040,1037,1033
 1040 IF (2-MODEOP)1041,1037,1033
      ...
```
Likewise, internal-procedure calls such as `EXEC LK_TABLE` expand into computed-GOTO dispatch of
the form `GO TO(<address>),IQnnnn`. **The hard-to-read goto soup in `wt9x.f` is the mechanical
expansion of these `DO CASE` + `EXEC`/`PROCEDURE` constructs** — the key insight for maintenance.

## 4. Known quirks / gotchas (encountered during real work)

1. **★ A semicolon `;` inside a comment is dangerous** (as specified in `docs/fpl90.doc §2.3`).
   `/` and `/*` comments **terminate at `;`**. Putting a `;` anywhere inside the comment text ends
   the comment there, and the remaining text leaks out as FORTRAN — causing "Unclassifiable
   statement" and similar errors.
   **Fix**: never use `;` inside an FPL comment (use `.` or `--` instead).

2. **Long-line wrap corruption**. If a long logical line (a `CALL`, a declaration, etc., including
   `--` continuations) is too long, the way FPL folds it into fixed form can emit a follow-on line
   at column 7 *without* the column-6 continuation mark `*`, producing an orphaned statement
   (syntax errors, undefined labels).
   **Fix**: keep each logical line short (split a long argument list across more `--` lines).

3. **Continuation requires `--`**. It is not the plain-FORTRAN "continuation character in column 6".
   To span lines, place `--` at the end of the line.

4. **Do not edit `*.f` directly**. They are generated and get overwritten by regeneration from
   `*.fpl`. Make fixes on the `*.fpl` side and regenerate with `./fpl < X.fpl`. **A build may
   regenerate `*.f`**, so after building you may see unintended `*.f` diffs (e.g. the generation-date
   header) → if unwanted, `git checkout -- <generated.f>`.
   - **A regenerated `*.f` may not be byte-identical to the committed one** — this is a real risk
     category to keep in mind, not a hypothetical. The recurring, benign cause is the
     `*     GENERATED BY FPL90 V(...  <date>)` header line, which is stamped with the *current*
     date on every regeneration. Verified 2026-07-05: regenerating `ciai.f` and `mcscf4.f` changes
     **only** that header line — the code bodies are unchanged. So a *body-level* diff after a
     regeneration signals a genuine `.fpl` source change (or a stale committed `.f`), whereas a
     header-only diff is just the date stamp (discard with `git checkout -- <file>`).
   - `mcscf4.f` was once flagged as "stale vs `mcscf4.fpl`"; that was incorrect — it is in fact
     **in sync** (regenerates identically apart from the date header). `mcscf4` is, however, dead
     code (no built object calls `MCSCF4`; only the unbuilt `mcscf5.fpl`/`mcscf6.fpl` reference
     it), so it is exercised by no test — see the maintenance note at the top of `mcscf4.fpl`.
   - Subtlety: FPL bakes the physical source-line numbers into the generated `.f` for its
     diagnostic/abort machinery, so **adding or removing comment lines in a `.fpl` shifts those
     numbers** — the recompiled `.o` can differ in the line-number constants even when the `.f`
     changed only in comments. Harmless (it only affects the line numbers printed in error
     messages), but "comment-only source change" is not always "byte-identical object".

5. **Compilation side-effect (PATH dependency)**. `fpl` is invoked by a relative name from the
   build directory, so if the build directory is not on `PATH` when you run `make`, you get
   `fpl: not found` (Error 127) (in containers etc., `export PATH=<builddir>:$PATH`).

6. **`DO CASE` branches generate goto/statement-number-heavy code**. When reading, map it back to
   the original `*.fpl`'s `DO CASE` / `EXEC` (Example 3). Conversely, tracing control flow from the
   generated `*.f` alone is hard.

7. **Macro name collisions / case**. `%name` is case-insensitive. You may unintentionally pull in a
   same-named macro from `include/`, so give local `%%..%` definitions clear names.

## 5. Relationship to `docs/fpl90.doc`

- **`docs/fpl90.doc` (FPL90 MANUAL, JAN 1993) is the primary, authoritative reference.** Its
  structure: §1 Introduction / §2 Source Structure (2.1 card format, 2.2 continuation, 2.3 comment)
  / §3 Syntax (the full BNF-style grammar) / §4 Macro Substitutions / §5 Sample Programs (N-Queens:
  source + compile listing + output, and FPL90 itself) / §6 Contents of the FPL diskette. **For
  fine syntax details and the full BNF, refer to it.**
- This document (`FPL_LANGUAGE_SPEC.md`) is a quick reference that **supplements the manual with how
  FPL is actually used in this codebase**. In particular, the following are hard to glean from the
  manual alone and are covered here:
  - The **auto-inclusion** of macro libraries via `include/` (`%NAME` → `include/NAME`), and the
    roles of this codebase's specific macro families (`%WORKCORE`, `%COMxxx`, `%WKCORE`, `%CHECK`,
    `%ACTION`, etc.).
  - Unix-build specifics: the output extension is `.f` (not the MS-DOS/mainframe manual's `.FOR`, or
    `.INC`/`FPLLIB.INCL`). Macros come from the `include/` directory.
  - Gotchas found during real work (Section 4; especially the **`;` inside comments**, long-line
    wrapping, and `*.f` regeneration).
- **Minor discrepancies with the manual**: the `PROCESS` header option is spelled `HEADDER` (two
  D's) in manual §3, but the actual `*.fpl` files use `HEADER` (and the real build compiles, so the
  preprocessor accepts it). Also the manual's `FILE`/`INCLIB` default behavior is described for
  MS-DOS/mainframe and differs in notation from the Unix build's actual behavior (`file 'x.f'`,
  `include/`).

### Appendix: FPL reserved words (from `docs/fpl90.doc §3 note`)
`DO, IF, END, FOR, PUT, ELSE, EXEC, EXIT, LIST, THEN, BEGIN, WHILE, UNTIL, BINARY,
FORMAT, FORTRAN, PROCESS`
(A statement that starts with anything other than these is treated as a plain FORTRAN statement
and passed through.)
